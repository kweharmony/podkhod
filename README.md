# Персональный фитнес-ассистент

Учебный проект по курсу «Fullstack», 1 семестр.
Дневник силовых тренировок: записываешь подходы и видишь, растут ли рабочие веса.

## Стек

Frontend:

- React + TypeScript, сборка через Vite
- React Router — маршрутизация
- shadcn/ui (на Tailwind CSS и Radix UI) — библиотека UI-компонентов
- Recharts — графики прогресса
- Lucide — иконки
- ESLint — проверка кода


## Назначение

Приложение хранит историю тренировок и считает по ней метрики прогресса:
объём тренировки, расчётный 1RM по упражнению, динамику замеров тела.

## Пользовательские сценарии

1. **Провести тренировку** — создать тренировку на сегодня, добавить упражнения,
   записать подходы (вес × повторения), сохранить.
2. **Повторить прошлую тренировку** — скопировать прошлый комплекс и подставить новые веса.
   При добавлении упражнения видно результат прошлого раза.
3. **Найти упражнение** — фильтры по группе мышц и оборудованию, поиск по названию.
4. **Посмотреть прогресс по упражнению** — график рабочего веса и 1RM по датам.
5. **Внести замеры тела** — вес и обхваты раз в неделю, график динамики.

Вложенные маршруты (3.1, 3.2, 4.1) отдельными экранами не считаются, но нужны роутеру.
Упражнение в маршруте прогресса — query-параметр, потому что это фильтр вида,
а не отдельная страница: экран тот же, меняется только выбранное упражнение.

### Решения по интерфейсу

- Список упражнений с фильтрами — один переиспользуемый компонент. В справочнике клик
  открывает описание, в тренировке он же показывается в модальном окне и добавляет
  упражнение. Экран тренировки при этом не размонтируется и введённые подходы не теряются.
- Карточка упражнения — часть справочника, отдельным экраном не считается.
- Состояние активной тренировки хранится в React Context, а не в компоненте страницы,
  чтобы данные не пропадали при переходе на другой экран.
- Два layout: публичный (визитка — логотип и кнопки входа) и основной (меню разделов).
  Гостю разделы приложения недоступны, поэтому общее меню ему не показывается.
- Пол выбирается при регистрации и хранится в профиле: от него зависит модель
  на анатомических схемах мышц и расчёт расхода калорий.

## Модель данных

| Таблица | Поля | Связи |
|---|---|---|
| `user` | email, name, height_cm | у пользователя много тренировок и замеров |
| `exercise` | name, body_part, equipment, target, instruction | общий справочник, без владельца |
| `workout` | user_id, date, title, note | принадлежит пользователю |
| `workout_exercise` | workout_id, exercise_id, position | связывает тренировку и упражнение |
| `set` | workout_exercise_id, weight, reps | подход внутри упражнения |
| `measurement` | user_id, date, weight, chest, waist | принадлежит пользователю |

```
user ──┬── workout ──── workout_exercise ──── set
       │                      │
       └── measurement        └── exercise
```

Связь «многие ко многим» между тренировкой и упражнением сделана через таблицу
`workout_exercise`: одна тренировка содержит много упражнений, а упражнение
встречается во многих тренировках.

Удаление каскадное: удалили тренировку — удалились её упражнения и подходы.

На сервере считаются: объём тренировки (сумма вес × повторения), расчётный 1RM
по формуле Эпли и ИМТ по росту из профиля.

## Запуск

### База данных

Нужен Docker. Из корня репозитория:

```bash
docker compose up -d
```

PostgreSQL поднимется на порту 5432.

### Backend

Нужен Python 3.11 или новее.

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate         # Windows
pip install -r requirements.txt
copy .env.example .env          # Windows
uvicorn app.main:app --reload
```

Таблицы создаются автоматически при первом запуске.

API: http://127.0.0.1:8000
Swagger с описанием всех методов: http://127.0.0.1:8000/docs

### Frontend

Нужен Node.js 20 или новее.

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется на http://127.0.0.1:5173

Фронтенд пока работает на демонстрационных данных из
`frontend/src/data/demo.ts`. Подключение к API — в ЛР №5.
